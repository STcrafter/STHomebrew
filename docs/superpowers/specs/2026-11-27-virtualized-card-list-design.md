# Виртуализация списка карточек — короткий дизайн

## Намерение
Список категорий (`src/pages/CategoryList.jsx`) рендерит все отфильтрованные карточки сразу. Больше всего данных в «Монстрах» — 88 записей. Нужно ограничить DOM только видимыми карточками без изменения текущего вида адаптивного CSS-grid и без потери существующих SSR-тестов.

## Подходы
1. **react-virtuoso (выбран)** — `VirtuosoGrid` умеет переменную высоту элементов и адаптивную сетку, сохраняет текущий UI, добавляет одну зависимость.
2. Свой виртуальный грид на scroll-слушателе — без зависимостей, но требует фиксированной высоты карточек и числа колонок, что изменит вид.
3. Постепенная загрузка по sentinel — проще всего, но DOM в конце всё равно вырастает до всех элементов; это не полная виртуализация.

## Конструкция
- Добавить зависимость `react-virtuoso`, заменить `<div className={styles.grid}>{filteredItems.map(...)}</div>` на `<VirtuosoGrid>` с `useWindowScroll` (страница прокручивается целиком, как сейчас).
- `listClassName={styles.grid}` и `itemClassName={styles.gridItem}` сохраняют отступы и колонки; разметка самой карточки не меняется.
- Передавать `initialItemCount` только при серверном рендере (`typeof window === 'undefined'`): в SSR/тестах рендерятся все карточки, в браузере виртуализация работает сразу. Если передавать число и в браузере, `VirtuosoGrid` ждёт прокрутки и короткие категории остаются пустыми.
- Задать `style={{ height: '100vh' }}` на `VirtuosoGrid`: без явной высоты корневой элемент Virtuoso схлопывается, и список остаётся пустым.
- При смене категории/поиска/фильтров сбрасывать прокрутку списка к первой карточке через ref, чтобы не показывать случайное место старого списка.
- Пустое состояние «Ничего не найдено» оставить как есть.

## Ограничения и не-цели
- Не виртуализируем страницу деталей и таблицы; только сетку карточек.
- Не меняем стили карточек, сортировку и фильтры.
- Не добавляем paginator.

## Проверка
- RED-тест: при рендере списка в jsdom с `VirtuosoGridMockContext` карточек должно быть меньше, чем элементов данных; отдельно проверить SSR-совместимость (все карточки в серверном HTML) и сброс к первой карточке при смене сортировки.
- Дополнительно проверить в реальном браузере: прокрутка окна меняет видимый диапазон карточек, смена сортировки возвращает к первой карточке.
- Полный `npm test` и `npm run build` после реализации; сборка не должна вернуть предупреждение о размере бандла.
