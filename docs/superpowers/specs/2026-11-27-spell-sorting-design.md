# Сортировка заклинаний — краткий дизайн

## Зачем

В разделе «Заклинания» сейчас доступна только сортировка по алфавиту. Нужны дополнительные варианты, чтобы быстро группировать заклинания по уровню, школе и классу, не теряя алфавитного порядка внутри каждой группы.

## Цели

- В панели инструментов вместо набора кнопок сортировки сделать два отдельных элемента:
  1. **Кнопка направления** — только переключает порядок ↑/↓, не меняет тип сортировки.
  2. **Выбор типа сортировки** рядом с ней — «По алфавиту», «По уровню», «По школе», «По классу».
- Внутри группы с одинаковым ключом (уровень / школа / класс) заклинания идут по алфавиту по названию.
- При смене типа сортировки направление сбрасывается на ↑; кнопка направления сохраняет выбранный тип.

Вид панели (существующие стили и токены темы):

```text
Сортировать: [ По алфавиту ▾ ] [ ↑ ]   ⭐ Только избранное
```

Селектор типа — нативный `<select>`, оформленный под существующие кнопки (те же цвета, рамка, скругление). Стрелка — отдельная `<button>` с `title`/`aria-label`, отображает ↑ или ↓.

## Не цели

- Не менять сортировку на странице отдельного заклинания (prev/next остаётся по алфавиту).
- Не менять фильтры, поиск, карточки и избранное.
- Не сохранять выбранную сортировку между переходами и перезагрузкой (как и сейчас).
- Не добавлять заголовки групп в список — только менять порядок карточек.

## Ограничения и решения

- У заклинания `level: number`, `school: string`, `classes: string[]` (классов может быть несколько).
- Ключ сортировки по классу — **первый по алфавиту** класс из `classes` (по `localeCompare`), чтобы карточка не дублировалась и порядок групп не зависел от порядка элементов в данных.
- Вторичная сортировка по названию всегда по возрастанию, даже при ↓ основной сортировки (по просьбе пользователя «внутри одной категории сортировка всё ещё в алф. порядке»).
- Сравнение строк — `localeCompare` с приведением к нижнему регистру, как в текущей сортировке по алфавиту; уровень сравнивается числом.

## Подходы

1. **Переделать существующую панель: один селектор типа + одна кнопка направления; компараторы расширить в `filteredItems` (выбран).** Состояние `sortField`/`sortDirection` уже есть, стили кнопок можно переиспользовать. Минимум кода, доступное управление с клавиатуры.
2. Оставить четыре кнопки и просто добавить две новые — отклонено пользователем: кнопка должна менять только порядок.
3. Кастомный выпадающий список на `<button>` + меню — выглядит как «кнопка выбора», но требует дополнительного состояния, обработки клика вне меню и клавиатуры; нативный `<select>` проще и надёжнее.

## Что остаётся реализатору

- Заменить цикл кнопок `sortOptions` на селектор и кнопку направления.
- Добавить компараторы для `level`, `school`, `classes` с вторичным сравнением по `name`.
- Сохранить сброс направления на `asc` при смене типа сортировки.
- Добавить стили селектора и кнопки направления в `CategoryList.module.css`, используя существующие переменные темы.
- Проверить сборку (`npm run build`) и вручную проверить все четыре режима и оба направления.
