# Design: статблоки внутри заклинаний

- Дата: 2026-11-27
- Статус: ждёт утверждения

## Зачем

В заклинаниях, которые призывают или создают существ, сейчас можно только описать эффект текстом. Нужно показывать компактный оформленный статблок прямо на странице заклинания, не заводя для него отдельную карточку в разделе «Монстры».

## Что решили с пользователем

- Статблоки выводятся **всегда в конце** страницы заклинания: после описания и раздела «На более высоких уровнях». Маркер в тексте не нужен.
- Внешний вид — как у статблока монстра, но в ужатом варианте А:
  - оставляем имя и тип, КД/ХП/скорость, таблицу характеристик со спасбросками, навыки, уязвимости/сопротивления/иммунитеты, чувства, языки, ОП, особенности, действия, бонусные действия и реакции;
  - убираем описание, изображение, легендарные действия, действия логова, описание логова, лор и места обитания.
- Отдельной страницы/карточки в монстрах нет.
- Конкретные существа изHomebrew живут только в своём заклинании, поэтому их данные кладутся прямо в `spells.js`. Возможность задать статблок во внешнем файле сохраняется для будущих повторно используемых блоков.

## Цели

1. Показывать один или несколько компактных статблоков на странице заклинания.
2. Поддерживать два способа задания данных:
   - inline-объект внутри заклинания;
   - ссылка на id во внешнем реестре статблоков.
3. Не дублировать вёрстку и стили `StatBlock`.
4. Не добавлять новых зависимостей.

## Не-цели

- Не делать из этих статблоков полноценных монстров.
- Не добавлять их в `monsters.js`, в список монстров или в навигацию.
- Не менять поведение существующих страниц монстров.
- Не вводить разметку в тексте описания.

## Подход

Принятый подход: **расширить существующий `StatBlock` режимом `compact` и добавить к заклинанию поле `statblocks`.**

### Данные

Новый файл `src/data/statblocks.js`:

```js
export const statblocks = {
  some_reusable_id: { /* обычные поля статблока */ },
};
```

В записи заклинания:

```js
statblocks: [
  'some_reusable_id',                 // строка = взять из реестра
  { id: 'spirit_servant', /* ... */ }  // объект = статблок прямо здесь
],
```

Оба вида элементов можно смешивать. Порядок в массиве — порядок вывода на странице. Для фактических призывных существ используется inline-форма; реестр остаётся опциональным.

Разбор списка выносится в чистую функцию в `src/utils/statblocks.js`: она принимает элементы и реестр, возвращает массив объектов. Неизвестный id даёт видимое предупреждение того же типа, что уже используется для отсутствующих таблиц.

### Компонент

`StatBlock` получает prop `compact = false`.

В компактном режиме:
- в шапке добавляется имя (`data.name`), которого нет на обычной странице монстра;
- скрываются `description`, `image`, `legendary_actions`, `lair_actions`, `lair_description`, `lore`, `habitat`;
- остальные секции работают как сейчас, включая списки заклинаний внутри действий и особенностей.

Обычный режим остаётся без изменений.

### Страница заклинания

В `ItemDetail.jsx` в ветке `spells` после `higher_levels` выводятся все разрешённые статблоки подряд через `<StatBlock monster={block} compact />`. Между карточками — отступ через CSS-класс в `ItemDetail.module.css`. Дополнительного заголовка типа «Статблоки» нет.

## Рассмотренные альтернативы

- **Отдельный `CompactStatBlock`** — отклонён: дублирует разметку и CSS, легко расходится с основным компонентом.
- **CSV-реестр, как у таблиц** — отклонён: у статблока вложенные массивы и объекты, CSV для них неудобен.
- **Маркер `[statblock:id]` в тексте** — отклонён пользователем: статблоки всегда в конце.

## Что остаётся на реализацию

- Файл реестра и pure-функция разрешения ссылок.
- Prop `compact` и условный рендер секций в `StatBlock`.
- Вывод статблоков в `ItemDetail.jsx` и отступы в CSS.
- Тесты `node:test` на разрешение inline/внешних записей и отсутствующих id.
- Проверка `npm test` и `npm run build`.
- `.superpowers/` уже добавлен в `.gitignore`.
