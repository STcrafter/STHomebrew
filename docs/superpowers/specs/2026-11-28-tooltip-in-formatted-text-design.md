# Дизайн: `[tooltip:...]` в `renderFormattedText`/`renderFormattedFeature`

## Намерение

Синтаксис `[tooltip: текст]` сейчас работает только на страницах `homerules`, потому что те рендерятся через `Markdown`. Во всех остальных категориях используется `renderFormattedText`/`renderFormattedFeature`, где подсказки нет: уже имеющаяся подсказка в `src/data/subclasses.js` видна как сырой текст. Нужно, чтобы один и тот же синтаксис работал и в старом форматтере, не меняя остальную разметку и не переписывая страницы на `Markdown`.

## Цели

- `[tooltip: текст]` в любом описании, feature или другом тексте, проходящем через `renderFormattedText` или `renderFormattedFeature`, превращается в такой же кружок `i`, как в `Markdown`: подсказка по hover и по фокусу с клавиатуры.
- Сохранить текущие возможности старого форматтера: абзацы, переносы строк, `**жирный**`, `[table:id]`, экранирование HTML.
- Не трогать `Markdown`, страницы, статблоки и данные.

## Не-цели

- Переносить все страницы на `Markdown` и удалять старый форматтер.
- Менять поведение подсказок внутри `Markdown` (в том числе то, что `**...**` внутри `data-tip` показывается как обычный текст).
- Добавлять клик/tap, ARIA-связывание и прочие улучшения доступности.
- Поддержку тултипов в сырых строках, которые рендерятся React напрямую (например, описание выбранного подкласса в `ClassDetail`).

## Подход

Добавить разбор тултипов в `src/utils/helpers.js` и стили в `src/index.css`. Конвейер `renderFormattedText` → `[table:id]` → абзацы остаётся тем же; меняется только то, как собирается содержимое абзаца.

### Разбор абзаца

- Вместо сборки HTML-строки с `dangerouslySetInnerHTML` абзац собирается из React-узлов: обычный текст, `<strong>` для `**...**`, `<br />` для переносов и `<span className="formatted-tooltip" tabIndex={0} data-tip={...}>i</span>` для `[tooltip:...]`.
- Текст подсказки берётся как есть (с trim по краям) и попадает в атрибут `data-tip`; React сам экранирует атрибут. HTML внутри подсказки не превращается в элементы. Вложенная разметка вроде `**жирный**` внутри подсказки остаётся текстом — так же, как сейчас в `Markdown`.
- Жирный текст внутри обычного текста продолжает работать по старому нежадному правилу `**...**`.
- Пустой `[tooltip:]` тоже создаёт маркер с пустой подсказкой; отдельной обработки не требуется.

### Feature

- `renderFormattedFeature` добавляет название жирным курсивом в первый абзац описания, передавая готовый React-узел `<em><strong>Название.</strong></em>` внутренней функции рендера. Сейчас подставленная HTML-строка экранируется и отображается как буквальный текст; после изменения название выводится как настоящий `<em><strong>` — это небольшое видимое исправление, одобренное отдельно. Ветка «описания нет» остаётся без изменений.

### Стили

- В `src/index.css` добавить `.formatted-tooltip` и правила `:hover`/`:focus`, повторяющие внешний вид и поведение подсказки из `Markdown.module.css` (кружок, `::after` с `content: attr(data-tip)`, стрелочка, появление по наведению и фокусу, `:focus-visible`-контур). Селекторы не завязываются на `.markdown`, чтобы работать во всех категориях.

## Рассмотренные альтернативы

1. **Замена всех вызовов на `Markdown` (выбранный ранее путь).** Даёт один рендерер на всё приложение, но требует доработки парсера под инлайновые `[table:id]`, создания режима для feature и может изменить внешний вид описаний. Больше риска и diffs — отклонено по просьбе.
2. **Обёртка `renderFormattedText` над `Markdown`.** Меньше кода в вызовах, но оставляет два конвейера с разными стилями и не убирает дублирование — отклонено.
3. **Локальная поддержка тултипов в старом форматтере (выбрано).** Минимальный радиус изменений: один модуль плюс CSS; страницы, данные и `Markdown` не трогаются.

## Что остаётся исполнителю

- Проверить `npm test` и `npm run build`, а также вручную открыть страницу `subclasses/reliquarian` в браузере.
